# 零界 / ZERO LINE

离线 Three.js 第一人称游戏. 保留整个目录, 双击 `index.html`; 无需安装或联网. 默认镰仓高校前, 菜单可切换工业训练场. WASD 移动, 鼠标观察/左键射击, R 换弹, Space 跳跃, Shift 奔跑, Esc 暂停. 竖梯旁 W 上爬/S 下爬, Space 跳离. 鼠标锁定失败时按住右键观察.

## 从哪里继续开发

先读 [agent.md](agent.md), 然后只读本页与本次修改涉及的源码. 文档只保留接口和约束, 不记录逐次开发历史或复述实现细节.

| 文件 | 职责 / 修改入口 |
| --- | --- |
| `index.html` | `boot` 加载, `createInstance` 装配, `frame` 唯一主循环; 通用玩家控制, 物理, 射击, 音效, HUD, 调试和容错 |
| `scene-kamakura.js` / `scene-layout.js` | 镰仓 / 工业场景; `catalog`, `instances`, 玩家出生点, 光照, 环境和介绍 |
| `models/` | 程序模型及其材质/纹理/动画; `rifle.js` 是主人物手臂与武器, `enemy.js` 是敌人行为 |
| `tools/build-vendor.mjs` → `vendor/` | Three.js 精简导出与离线产物; 缺少 API 时补导出并执行 `npm run build:vendor`, 不手改产物 |

加载链: 场景配置 → `catalog` 加载普通脚本 → `instances` 调用工厂 → `frame` 调用模型回调. 改造型只改模型, 改摆放只改场景, 只有通用能力缺失才改 HTML. `load()` 为所有脚本附加版本戳, 避免 file:// 缓存旧代码.

## 新增单文件 / 文件夹模块

1. 简单模块用 `models/beacon.js`; 需要独立目录时用 `models/beacon/index.js`. 文件夹只是组织方式, 入口仍自包含, 不自动扫描目录. 禁用运行时 import/export, fetch 和跨模型依赖, 保证 `file://` 可用.
2. 入口注册工厂, 返回 `root`; 几何体和材质全部留在该文件:

```js
FPS.models.beacon = (T, options) => {
  const root = new T.Group();
  const mesh = new T.Mesh(new T.BoxGeometry(1, 1, 1),
    new T.MeshStandardMaterial({ color: options.color ?? 0x668877 }));
  mesh.position.y = .5;
  root.add(mesh);
  return { root };
};
```

3. 在目标场景的 `catalog` 增加 `beacon: 'models/beacon/index.js'`, 在 `instances` 增加:

```js
{ id: 'beacon-1', model: 'beacon', position: [0, 0, 10],
  options: { color: 0x668877 },
  collision: { enabled: true, size: [1, 1, 1], offset: [0, .5, 0] } }
```

这样无需修改主循环. 注册名与 `model` 对应, 实例 `id` 唯一; 同模型可重复实例化. 修改后刷新页面.

## 必要接口与边界

- 清空敌人后结算胜利. 游玩中按 U 移除所有敌人 (不触发胜利), 再按 U 按初始配置满血刷新并重置击杀数; 不重置玩家状态.
- 工厂可选 `factory.preload(options, { compute })`, 通过 `compute(function, input)` 提交自包含的同步数据生成函数; 工厂第三个参数接收结果, 缺少结果时保留原同步装配. 线程函数只返回普通对象/数组/TypedArray, 不依赖闭包, Three.js 或 DOM; 可使用 OffscreenCanvas, 缺少能力或线程失败时自动回退主线程. 启动按硬件核心数最多并行 3 个 Blob Worker, 只转移输出缓冲, 不转移配置; 返回后终止线程并释放 Blob URL. 网格/材质/碰撞仍按原实例顺序装配, 每批约 8 ms 后让出事件循环, 单个同步工厂不被中断. 公园地面/山体纹理和枯山水砂底启用预生成, 不降低纹理分辨率或改变随机序列.
- 加载耗时由 `FPS.inspect().loading` 返回 `totalMs/phases/models/tasks`; `phases` 是各阶段墙钟耗时, `models[].ms` 只包含主线程装配, `tasks` 记录并发上限/线程启动/回退/完成次数, 不用装配时间冒充完整生成时间. 游戏开始前完成所有预生成任务, 不在游玩时保留生成线程.
- 常驻动画可返回 `update(dt, api)`, 仅在游戏进行时更新, `dt` 单位秒; 不创建计时器或额外动画循环. 静态模型不必提供回调.
- 入场前先调用 `prepare(renderer, scene, camera)` 接入环境/材质补丁和私有缓冲, 再异步编译世界并在 32² 离屏缓冲上传资源; 不在编译前同步渲染全图. 静态太阳图生成后烘焙地表缓存, 武器只编译自身子树并实际上传, 不重复编译全图的屏幕输出版本. GPU 等待限 5 秒并处理驱动/上下文失败, 进入按钮在准备完成后启用; 准备异常仍隔离单模块. 视锥包围球在装配时预计算, 已有的模型自定义风动/动画范围原样保留.
- 辅助渲染可返回 `beforeRender(renderer, scene, camera)`, 在世界渲染前调用; 必须恢复渲染状态, 用 `dispose()` 释放自有资源. `character-shadows.js` 独立更新角色深度图, 玩家简化身体仅参与投影. 动态阴影相机连续跟随玩家, 不对齐静态世界的像素格; 腿部按移动距离以 2.5 rad/m 推进并按时间平滑走停, 暂停/重复预渲染不重置姿态. 角色投影范围外跳过采样, 范围按真实实例变换保守包围并留出过滤余量; 3×3 二次权重过滤逐样本补偿接收坡面深度, `bias` 使用世界米制, 默认 .006 米, 不增大深度图或添加绘制通道.
- 场景至多一个模块可返回 `render(renderer, scene, camera)` 接管世界渲染, 可附 `dispose()` 释放自有缓冲; 异常时禁用并恢复普通渲染. `sun-rays.js` 只输出单个 HDR 颜色附件, 按 HDR/深度共同支持的采样数选择最高 4x MSAA, 不注入世界材质或改动叶片覆盖率/透明度. AO 使用半分辨率单缓冲和 12 次固定采样, 默认 `aoRadius: .85`, `aoStrength: .42`, `aoDistance: 40`; 从 70% 距离开始淡出, 远处跳过邻域采样. 合成时用双线性/深度权重及斜面容差过滤, 不增加独立过滤通道. 单缓冲 AO 是亮度权重的接触遮蔽近似, 不分离间接光; 高亮区域压暗较少. `samples/strength` 只控制迎光光束, 无可见光束时跳过其绘制和纹理读取; 武器/HUD 仍在后续通用流程中绘制, 缺少浮点缓冲支持时恢复普通渲染. 角色材质补丁须保留原回调/缓存键, 支持共享材质释放后复用及卸载.
- `attach: 'camera'` 挂载第一人称武器, 接收 `{ time, walk, recoil, reload }`, 可返回 `muzzle`. 参考 `rifle.js`; 保留两场景的主人物, 调试飞行时暂时隐藏武器.
- 敌人返回 `alive`, `damage(amount, api)`, `update`; `damage` 会使实例计入敌方目标. API 有 `player`, `eye()`, `move(root, dx, dz, radius, height)`, `visible(from, to)`, `shoot(from, direction, team, damage)`, `effect(name, options)`, `killed(actor)`. 方向需归一化, `team` 为 `player` 或 `enemy`, 死亡只调用一次 `killed`.
- 可破坏物及地面返回 `onHit(hit, api)`, 不使用敌人的 `damage`; `hit` 含射线命中信息及 `direction/normal/damage/team`, 返回 `{ bulletmark: false, impact: false }` 可分别取消默认弹痕和火花, `{ bulletmark: false, surface: 'soil' }` 改用短暂土屑. 静态碰撞实例及实现 `onHit` 的非角色世界实例参与射击, 地面无需增加身体碰撞即可遮挡下面的地基; 水面通过 `onHit` 触发独立 `water-splash.js`, 碎片通过独立临时特效生成.
- 临时特效只登记 `catalog`, 通过 `api.effect` 创建; 返回 `duration` 与可选 `update(dt, progress)` / `dispose()`, `progress` 为 0–1. 到期, 限额淘汰或附着对象移除时, 主程序先调用私有资源清理, 再释放几何/材质; 清理异常不阻断回收. 不与常驻模型共享会被释放的资源. 参考 `tracer.js` / `bulletmark.js`.
- 坐标单位米, Y 向上, 旋转为 XYZ 弧度. `rotation` 默认全零, `scale` 默认全一. 碰撞尺寸用局部坐标, 复杂模型用 `collision.boxes: [{ size, offset }]`; 静态盒仅创建时转换为世界 AABB, 不跟随动画, 斜放会扩大范围.
- 太阳光 `shadowBias` 使用阴影相机归一化深度, `shadowNormalBias` 使用世界米制, 缺省分别为 -.0004 / .035; 大范围地图应按实际深度跨度校准, 避免物体与接触影分离. 镰仓配置 -.000015 / .008, 闭合树干/山石材质显式使用迎光面 `shadowSide: THREE.FrontSide`, 阴影相机/贴图尺寸和静态缓存保持原规格.
- 动态身体使用 `collision: { enabled: true, dynamic: true, radius: .42, height: 1.9 }`, 原点在脚底, 需要角色伤害接口. 主程序负责移动/重力/身体阻挡; 射击只认网格三角面, 弹痕用实际命中点与世界法线 (包含实例变换), 装饰线不参与命中或遮挡. 未实现 `onHit` 且无碰撞的装饰实例不自动成为射击目标. 通用行走支持最高 `STEP_HEIGHT = .28` 米的台阶上下, 仅落地且抬升空间足够时自动登阶; 跳跃和高处跌落仍受重力控制.
- 台阶视角由主流程统一处理: 登阶/贴地换高时抵消瞬时高度变化, 偏移按 70 ms 时间常数消退并限制在 .42 米内; 每帧只推进一次, 转向/水平位移/跳跃仍直接响应. 落地行走按碰撞小步距检查支撑, 避免低帧率跨级触发自由落体. `syncPlayerCamera` 供移动/渲染/即时单击/继续共用, 玩家射线从当前相机发出以对齐准星, API `eye()` 保留物理眼高. 下阶高视点受顶棚和上方角色限制, 暂停保留偏移, 竖梯/调试/重生清除偏移; 不需要模型专用控制逻辑.
- 静态碰撞盒可附 `heightfield: { columns, rows, heights, maxSlope }`: 至少 2×2, 高度按 Z 行/X 列排列且在盒的局部 Y 范围内; 盒的 X/Z 尺寸与偏移定义网格范围, 模型共用高度与每格对角线. 主流程以脚底九点取最高支撑, 通用行走/落地/陡坡限制/调试退出和网格线框均支持; `maxSlope` 默认 .55 (高度变化/水平距离); 海望山使用 1 (45 度), 保留陡壁限制. 水平移动先检测完整向量, 受阻后再按轴贴边/登阶, 允许沿陡坡等高线横走和向下退回. 只用于直立静态世界实例, 支持水平旋转和正缩放, 不用包围盒顶面冒充地形.
- 静态世界实例可声明 `traversal.ladders: [{ bottom, top, normal, exit, width }]`: 坐标与朝向为局部值, 主流程加载时转换为世界路线, 随实例失效或移除停用. 梯身必须竖直, `normal` 指向登梯一侧, `exit` 为顶端内侧同高度落脚点, `width` 为梯宽. 靠近正面并朝梯子按 W 上爬, 顶端按 S 下爬; 松键悬停, Space 跳离, A/D 侧移脱离. 竖直移动和顶端过渡都保留静态/动态身体阻挡, 暂停保持位置, 调试飞行清除攀爬状态. 几何与路线共用场景规格, 模型只生成外观.
- 地面命中规则由各模型自有 `onHit` 定义: 草坪/林下草土, 沙滩/枯山水砂面与苔藓, 松散砂砾/道砟, 花坛/树池/宅院土面不留固定弹痕且不冒硬面火花; 混凝土/沥青/石板/石沿/踏石及木质/金属结构保留弹痕; 水面只产生水花. 混合合批网格按自身材质或合批面编号区分软硬面, 不拆网格或新增身体碰撞, 主流程只转发通用命中响应.
- 花叶与 `low-hedge.js` 灌木冠层不设碰撞; 花坛, 景石, 树干, 竹簇和围栏保持实体碰撞, 外围墙负责地图边界. 密集竹林按簇共用实体盒, 射击和视线仍只命中真实竹竿, 不把簇内空隙当实心墙.
- 避免可见表面共面, 否则移动时闪烁. 大量重复构件用 `InstancedMesh`, 静态构件按材质合并; 不用逐帧补丁掩盖建模问题.

## 当前场景与排查

- P 显示性能面板, 保持正常第一人称/碰撞/武器, 不依赖自由飞行. 最近三秒的前台游玩帧按实际 RAF 间隔计算 FPS (帧数/累计间隔), 物理仍限制单步 50 ms; 显示 P95 帧耗时, 最慢 1% 帧平均时间对应的 FPS, 最大帧耗时与 >50 ms 数量. 入场/恢复首帧和暂停/后台不采样, 切换自由飞行或敌人状态重置窗口, 至多 720 帧. 逻辑/HUD 和渲染提交分别计 CPU 时间, 不冒充 GPU 耗时; `renderer.info` 在整帧开始只清零一次, 累计阴影/倒影/世界/后处理/武器的实际 DRAW/TRI. `FPS.inspect().performance` 返回同口径快照. 稳定三秒后比较相同位置/分辨率/敌人状态, 硬件帧数需实际浏览器验证.
- 镰仓: `mode: 'combat'`, 4 名敌人, 复用 `enemy.js`; 电车停靠, 道口注意牌使用程序图案. `kamakura-ground.js` 管轨道; 海面, 云, 岛屿, 花叶各有独立文件. 电线合批, 路面裂纹烘焙到材质, 天空后绘制以利用深度遮挡; `coastal-sky.js` 提供程序环境贴图, `environmentIntensity` 默认 .38, 半球补光由场景灯光配置控制. `staticShadow` 缓存全图环境阴影, 不随玩家移动重绘附近环境或增加太阳光源. `characterShadows` 用独立 1024² 图更新角色投影, 敌人不写入环境缓存; 接收面仅在模型 root 首次接入或共享材质释放后扫描, 稳定帧不重复遍历静态网格. 移动光源时须关闭静态缓存并同步模块 `sun`. 性能参数为云 `steps`, `atmosphere.pixelRatio` 与 AO 作用半径/强度/距离.
- `kamakura-ocean.js` 按像素内的相位跨度过滤各档波纹与泡沫颗粒; 未解析的法线方差用于平均掠射反射并展宽高光, 保持远海亮度稳定. 近海网格只承载可采样的长波与近岸涌浪, 向粗远海/侧翼连续收平; 短波保留在材质法线. 港池共用材质/时间和接边顶点, 无新增渲染缓冲或主流程分支.
- `coastal-sky.js` 共用十二个云体定义密度与保守射线范围, 只跳过密度必为零的前后空段; 原采样位置/步数/三次光照探针保持不变. 密度形状先取归一化距离平方的最小值, 再开一次平方根, 不逐云体开方; 无新增缓冲或绘制通道.
- 工业: `?scene=industrial`, 6 名敌人及出生点 4 个木箱. `mode: 'explore'` 会禁用射击并隐藏战斗 HUD, 不要误用于当前两场景.
- 公园树保留全部可见细叶和风动, 叶面不接收细碎自阴影; 每棵树另用 84 张静态冠簇牌面 (168 面, 自有带孔轮廓 mipmap) 向地面投影. `onBeforeShadow/onAfterShadow` 只在阴影阶段打开代理的实例数和 drawRange, 世界/倒影与异常回退设零实例以跳过 GL 提交; 包围体在完整实例时固定, 不参与射击. 色写入/深度写入关闭保护普通绘制, 卸载释放两个实例缓冲. 树干仍直接投影, 不逐帧更新环境影图.
- 公园/榉树/樱花叶面及中央/山区草丛抵消 Three.js 双面材质的观察方向翻面, 向树冠外侧或坡面混合法线; 近垂直点积留出 Float32 容差. 树叶导数在透明裁切前计算, MSAA 覆盖率/原 mipmap/单采样回退均保留.
